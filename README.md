# プロジェクト原価管理システム（project-costing MVP）

工数 × 給与データ × MF会計PLUS のエクスポートから、**プロジェクト（花名）別の
全負荷原価と損益**を算出する社内ツールの試作版です。

現行の Excel 運用（推移表・事業部別損益）では
「人件費が事業部単位の丸ごと割当」「販管費・社宅コストがプロジェクトに乗らない」
という限界がありました。本システムは以下を実現します。

- **工数管理の導入**：従業員×プロジェクト×日の工数を記録（週次グリッド / 月次まとめの2方式）
- **全負荷人件費**：支給合計 ＋ 会社負担社会保険（料率推算）＋ 社宅純コスト
- **間接費のプロジェクト配賦**：MF会計の販管費科目を選択ドライバで配賦
- **単月/累計・予実対比**：プロジェクト → 事業部 → 会社の3階層でいつでも閲覧
- **突合レビュー**：並行運用期間中に現行Excelとの差異を可視化

## セットアップ

```bash
pip install -r requirements.txt
streamlit run app.py
```

初回はトップページの「デモデータを投入する」ボタンで、実データと同じ構造の
架空データ（2026-03〜05）が入り、全ページをすぐ試せます。

```bash
pytest tests/        # 配賦保存則・冪等性などの単体テスト
```

## データ維持の責任分担（手入力を最小化する設計）

| データ | 方式 | 頻度 | 手間 |
|---|---|---|---|
| 事業部・従業員・プロジェクト | 従業員は給与取込で自動作成。プロジェクトも実績取込で自動作成 | 初回＋異動時 | 極小 |
| 列マッピング・科目区分・部門対応 | 初回設定後は自動適用。新科目出現時のみ警告に従い区分設定 | 初回＋偶発 | 極小 |
| 年度予算 | 現行予算Excelから整形して一括取込 | 年1回 | 小 |
| 給与データ | CSV出力→アップロード（冪等・再取込可） | 月1回 | 小 |
| MF会計 推移表 | CSV出力→アップロード | 月1回 | 小 |
| 社宅台帳 | 入退去・家賃改定時のみ更新（各月への展開は自動） | 入退去時 | 極小 |
| デフォルト配分 | BSE管理表「投入project」列を取込 | 異動時 | 極小 |
| **工数** | **唯一の新規手入力**。週次グリッドまたは月次まとめ（%可） | 週/月 | 中 |

## 原価計算の仕様

1. **全負荷人件費** = 支給合計 + 会社負担社保（料率マスタ、既定15.5%相当）+ 社宅純コスト（会社支払家賃 − 本人負担）
2. **人件費配賦** = 全負荷人件費 × (プロジェクト記入工数 ÷ **給与実績の総労働時間**)
   - 分母を給与実績にすることで、記入漏れは「未配賦人件費」として顕在化し、
     記入済みプロジェクトの原価を歪めない（過大計上を防ぐ）
   - 工数未記入の従業員は BSE 由来のデフォルト配分でフォールバック（レポートで区別表示）
   - それも無い場合（管理部門など）は未配賦＝間接人件費として事業部・会社集計に表示
3. **間接費配賦** = MF会計で overhead 区分にした科目合計を、
   人件費比 / 工数比 / 売上比 のいずれかで当月活動のあるプロジェクトへ配賦
   - 保存則：配賦後合計 == プール合計（テストで強制）
4. **プロジェクト損益** = 売上 − 外注費 − 配賦人件費 − 配賦間接費

## 管理面の改善提言（システム導入と併せて）

1. **MF会計のタグ運用が最重要**：MF会計PLUSは部門・プロジェクト・取引先タグを
   標準サポートしています。仕訳ルールとして
   「売上高・外注費(製)は必ずプロジェクト（花名）タグ」「販管費は必ず部門タグ」
   を義務化すれば、間接費の多くが"配賦"ではなく"直課"になり精度が上がるうえ、
   プロジェクト実績取込（手作業）を MF エクスポートに一本化できます。
2. **工数は段階導入**：最初の1〜2ヶ月はPMによる月次まとめ入力（%配分）で開始し、
   慣れてから週次実録に移行。承認ページの「記入率」を月次KPIとして追う
   （記入率が低い＝未配賦が大きい＝原価が見えていない、が定量化されます）。
3. **社宅台帳の整備**：社宅の会社負担コストは現在どのシステムにもありません。
   総務にて「従業員・入居日・退去日・月額家賃（管理費込）・本人負担」を
   台帳化してください（テンプレートCSVは取込ページから取得可）。入退去時だけの
   更新で済みます。
4. **賞与・退職金の平準化**（次段階）：6月/12月の賞与は当月に全額乗せると
   単月原価が跳ねるため、月割引当で平準化する運用を検討してください。
5. **並行運用2〜3ヶ月**：突合レビューページで現行Excelとの差異が説明可能な
   範囲に収まることを確認してから、Excelの人件費・按分部分を廃止する。
6. **受注前案件との接続**（次段階）：業務一覧（商談パイプライン）の確度×金額と
   本システムの実績を接続すれば、着地見込み（フォーキャスト）まで一気通貫になります。

## 構成

```
app.py                     # トップ（KPI・デモデータ投入・運用ガイド）
pages/                     # Streamlit ページ（取込→工数→損益→突合→マスタ）
core/models.py             # SQLAlchemy スキーマ（SQLite）
core/allocation/engine.py  # 配賦エンジン（純pandas・単体テスト対象）
core/importers/            # 給与・MF会計・社宅・BSE・予算・実績の取込
core/reporting/            # 単月/累計・予実・突合の集計
core/seed.py               # デモデータ
tests/                     # pytest（保存則・冪等性・実フォーマット解析）
```

## 制限事項（MVP）

- 認証なし（社内ネットワーク内での試用を想定）
- SQLite 単一ファイル（同時大量書込みには不向き。本格運用時はPostgreSQL等へ）
- 会社負担社保は料率推算（正確な等級ベース計算は給与システム側の出力追加で置換可能）
- MF会計とのAPI連携なし（CSV手動アップロード。API化は次段階）
